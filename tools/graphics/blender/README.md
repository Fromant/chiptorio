# Blender entity pipeline

The canonical model is the approved **3 x 3 twin-bay server enclosure**.
`server-rack.blend` is editable; `build.py` rebuilds it from native geometry.
There are no downloaded preset dependencies or legacy template steps.

## One command

Requires Blender 5.2. Supply `-BlenderPath` when Blender is not on PATH.
From the repository root:

```powershell
# Rebuild, animate all four directions, pack sheets and install the graphics.
powershell -NoProfile -ExecutionPolicy Bypass -File tools/graphics/blender/render-entity.ps1 -Build -Animate -Device hip -GpuName 9070 -Install -BlenderPath 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe'
```

Static export is the default. Directions and animation are independent:

```powershell
# One static view, no game installation.
.\render-entity.ps1 -Angles north
# Animated single direction for review.
.\render-entity.ps1 -Angles east -Animate
# Full static install; generates a one-frame sprite definition.
.\render-entity.ps1 -Angles north,east,south,west -Install
# Animated export, alternate loop size and CPU rendering.
.\render-entity.ps1 -Animate -Frames 32 -Device cpu
```

Examples after the first command are run from this directory with Blender on
PATH; otherwise supply `-BlenderPath` as above. Install requires all four
cardinal directions. `-Angles` also accepts `hero`. `-NoShadows` omits shadows.
`-Samples`, `-Resolution`, `-OutputDirectory`, and `-KeepFrames` are independent
options. Re-render before repacking when intermediate frames were removed.

## GPU selection

`-Device auto` (default) selects a discrete AMD HIP GPU when available and
otherwise falls back to CPU, reporting the selection. `-Device hip` requires
HIP; `-GpuName 9070` selects the RX 9070 XT rather than integrated graphics.
Explicit device requests fail instead of silently switching to CPU. The
render manifest records the actual selected device. The final animation was
rendered with Cycles HIP on the AMD Radeon RX 9070 XT.

## Pipeline stages

- `build.py`: standalone materials, geometry, rig and named animation channels.
- `render.py`: renders the saved model, with optional animation and directions.
  Fans rotate about individual hubs. Seven blades repeat seamlessly after
  one-seventh of a revolution; lamps use staggered deterministic patterns.
  Frame-zero stills and one static shadow per direction are also exported.
- `pack.ps1`: packs frames left-to-right, top-to-bottom, validates dimensions,
  checks that animation changes and that every silhouette fits the 3x3 area,
  and emits `sprite-def.lua`. `-Install` copies only sheets, shadows and the
  generated definition into `graphics/entity/server-rack/`.
- `make-preview.ps1`: optional contact sheet. `preview.html` plays the exact
  exported sheets with a pause button; it is generated by the packing step.

Default animation: 16 frames, four columns, 30 fps (`animation_speed=0.5`).
Static mode uses one frame and needs no animation-specific prototype changes.
Blender renders never mutate prototypes. Installation is an explicit option.
No image-generation service or hand-edited PNGs are involved.

## Projection and alignment

One model unit is one tile. The camera and lighting are fixed at a 45-degree
orthographic view; only the enclosure rotates. All shadows fall to screen-right. No nonuniform scaling is applied. All directions use
one uniform sprite scale (0.475 at 384px resolution), preserving the approved
proportions. Packing computes a fixed shift from the union of all frame alpha
bounds so fans and blinking lights never make the sprite jump. Full cabinet
silhouettes fit within 96 x 96 game pixels; shadows may extend beyond it.

The model's static parts, emissive lamps, cable curves, rotors, rig and shadow
catcher remain editable in the native file. Rotor and lamp channels are named
on Blender objects/materials and evaluated by the renderer. Static export
uses their frame-zero pose.

## Factorio integration and verification

Providers remain lab clones. Labs cannot rotate natively, so the four render
variants share one provider profile; R / Shift+R uses `rack_runtime.lua` to
preserve modules, health, energy and position. The data stage consumes the
generated `sprite-def.lua` for static entity graphics and animation prototypes.
The runtime attaches an independent visual loop to each rack, so fans and
lamps animate even when the lab is idle or has no research. Render references
persist in storage and are recreated on configuration changes, rotation and
cloning. Ground shadows stay in the static entity graphics.

`tools/preview-rack.ps1 -Reload` opens the disposable comparison scene.
`-CollectScreenshot` copies its captures into `renders/final/`.
Existing player saves are not loaded. Headless verification remains
`tools/test-all.ps1` as documented in `docs/testing.md`.

Generated review files live in `renders/final/` (gitignored). Shipped assets
are the installed sheets, shadows and Lua definition in `graphics/entity/server-rack/`.
